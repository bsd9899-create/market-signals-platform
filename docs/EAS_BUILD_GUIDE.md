# تشغيل هِمّة فعليًا على آيفون — دليل EAS Development Build

## لماذا لا يمكن تنفيذ هذه الخطوة من داخل جلسة العمل هذه

بيئة هذه الجلسة تمر عبر بروكسي شبكة بسياسة صارمة (نفس السبب الذي منعها
سابقًا من الوصول إلى Supabase مباشرة). تم التحقق بشكل قاطع أن هذا
البروكسي يحجب أيضًا كل نطاقات EAS/Expo نفسها:

```
curl https://expo.dev      → CONNECT tunnel failed (403 connect_rejected)
curl https://api.expo.dev  → CONNECT tunnel failed (403 connect_rejected)
curl https://exp.host      → CONNECT tunnel failed (403 connect_rejected)
```

بمعنى آخر: **لا يمكن تشغيل `eas login` أو `eas build` من هذه الجلسة
مهما توفرت بيانات الاعتماد** — هذا حظر على مستوى الشبكة، وليس نقصًا في
حساب أو صلاحية. كل ما يمكن إنجازه من هنا (وتم إنجازه فعلًا) هو تجهيز
المشروع بالكامل ليكون جاهزًا للبناء بمجرد تشغيل الأوامر التالية من جهازك.

تم التحقق محليًا أن الإعداد صحيح عبر `npx expo prebuild --platform ios`
(يُولّد مشروع iOS الأصلي فعليًا من app.json بدون أي تحذير أو خطأ) —
هذه أقوى دليل ممكن من داخل هذه البيئة على أن إعداد EAS سينجح.

## المتطلبات قبل البدء

1. **حساب Expo (EAS) مجاني** — إن لم يوجد: انشئه في expo.dev.
2. **حساب Apple Developer Program مدفوع (99$/سنة)** — إلزامي من Apple
   نفسها لأي Development/Internal Build يعمل على آيفون حقيقي (وليس
   قيدًا من هِمّة أو من EAS). بدونه لا يمكن توقيع التطبيق لجهاز حقيقي إطلاقًا.
3. Node.js مثبت على جهازك، ونسخة من هذا المستودع (فرع
   `claude/new-session-5fqs4q`) مستنسخة محليًا.
4. آيفون حقيقي متصل بنفس شبكة الواي فاي أو عبر كابل USB.

## الخطوات (من جهازك، وليس من هذه الجلسة)

```bash
git clone <repo-url>
cd market-signals-platform
git checkout claude/new-session-5fqs4q
npm install

# 1) تسجيل الدخول إلى حساب Expo
npx eas-cli login

# 2) ربط المشروع بحساب EAS — هذا يضيف تلقائيًا extra.eas.projectId
#    و owner داخل app.json (لم يُضَفا من هذه الجلسة تحديدًا لأن
#    قيمتهما تعتمد على حسابك الفعلي في Expo، ولا يجوز اختراعهما)
npx eas-cli init

# 3) تسجيل جهاز الآيفون (يفتح رابطًا تفتحه من الآيفون نفسه لتسجيل UDID)
npx eas-cli device:create

# 4) البناء الفعلي — يستخدم بروفايل development الجاهز في eas.json
npx eas-cli build --profile development --platform ios
```

سيطلب EAS تسجيل الدخول بحساب Apple Developer أثناء أول بناء لإنشاء
شهادات التوقيع تلقائيًا (الخيار الموصى به: دع EAS يدير كل شيء).

## تثبيت النسخة على الآيفون

عند انتهاء البناء (يستغرق عادة 10-20 دقيقة على السحابة)، يعطيك EAS:

- رابط تثبيت مباشر + رمز QR في الطرفية وفي صفحة البناء على expo.dev.
- افتح الرابط/امسح الرمز **من متصفح Safari على نفس الآيفون المسجَّل**
  في الخطوة 3 → سيثبّت التطبيق كأي تطبيق عادي (Ad Hoc/Internal
  Distribution، بدون الحاجة لـ TestFlight في هذه المرحلة).
- أول مرة فقط: الإعدادات ← عام ← VPN وإدارة الجهاز ← ثِق بمطوّر
  التطبيق، ثم افتح التطبيق.

## بعد التثبيت — تشغيل الواجهة فعليًا

نسخة Development Build لا تحتوي حزمة الجافاسكربت مضمّنة داخلها؛ تحتاج
خادم تطوير يعمل بجانبها:

```bash
npx expo start --dev-client
```

افتح تطبيق هِمّة على الآيفون — سيتصل تلقائيًا (نفس الشبكة) ويعرض شاشة
تسجيل الدخول الفعلية. من هنا تقدر تجرب التنقل، الشاشات، RTL، والهوية
البصرية بشكل حقيقي على الجهاز. ميزتا HealthKit والاشتراكات ستعملان
فقط بعد ربط بيانات اعتماد RevenueCat الحقيقية (`.env`) وتسجيل دخول Apple ID
حقيقي على الجهاز لصلاحيات Health.

## بعد أول نجاح

- بمجرد أن يضيف `eas init` قيم `extra.eas.projectId` و`owner` داخل
  `app.json` على جهازك، ادفعها (commit) إلى نفس الفرع حتى تبقى الجلسات
  القادمة (من هذا الطرف) قادرة على متابعة العمل على نفس مشروع EAS.
