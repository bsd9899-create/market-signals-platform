# إعداد بريد المصادقة (OTP) — Resend + Supabase Custom SMTP

## الحل المحدَّد (بعد المراجعة والموافقة)

**لا حاجة لأي تعديل على كود التطبيق.** الكود الحالي في
`src/features/auth/api.ts` صحيح ومطابق للـ Production منذ البداية —
`signInWithOtp()` / `verifyOtp()` يرسلان "رمزًا أو رابطًا" حسب متغيّر
واحد في قالب البريد نفسه على مستوى Supabase (وليس في الكود):

- `{{ .ConfirmationURL }}` في القالب → يُرسَل رابط (Magic Link)
- `{{ .Token }}` في القالب → يُرسَل رمز من 6 أرقام (OTP) — وهذا ما تعتمد عليه شاشة `app/(auth)/verify.tsx`

المشكلة كانت بنيوية في مستوى Supabase فقط: بريد Supabase الافتراضي
(Default/Built-in SMTP) — منذ 3 يونيو 2026 — لا يسمح بتعديل القالب
إطلاقًا للمشاريع الجديدة على الخطة المجانية، وحتى بمعزل عن ذلك فهو
محدود بـ **2 رسالة/ساعة لكل المشروع**، ولا يصل فعليًا إلا لعناوين
البريد المسجَّلة كأعضاء الفريق — أي لا يعمل مع مستخدمين حقيقيين
إطلاقًا، بصرف النظر عن مسألة OTP. لذلك **Custom SMTP إلزامي لأي
إنتاج فعلي**، وليس اختياريًا لمجرد تفعيل OTP.

## المزوّد المعتمد: Resend

بعد المقارنة (Resend / Postmark / SendGrid / AWS SES / Brevo)، **Resend**
هو الأبسط والأنسب لحجم الاستخدام الحالي:

| | Resend |
|---|---|
| الخطة المجانية | 3,000 رسالة/شهر، 100/يوم — مجانية دائمًا (وليست تجربة محدودة) |
| التعقيد | الأبسط بين الكل — مفتاح API واحد أو بيانات SMTP مباشرة |
| التوثيق | دليل رسمي مخصص لـ Supabase: https://resend.com/supabase |
| التكلفة عند التوسع لاحقًا | تبدأ من $20/شهر لحجم أكبر (غير مطلوب حاليًا) |

## ⚠️ نقطة مهمة: لا يوجد دومين بعد

Resend **لا يرسل لعناوين مستخدمين حقيقيين إطلاقًا بدون توثيق دومين**
(بدون دومين موثّق تقدر بس ترسل لبريدك الشخصي المسجَّل في حساب Resend
نفسه — نفس قيد Supabase الافتراضي إلى حد كبير). لذلك الخطوة الأولى
الفعلية قبل أي شيء آخر:

1. **اشترِ دومينًا رخيصًا** (حتى لو غير الدومين النهائي للتطبيق لاحقًا) —
   `.com` عادة حوالي 10-15$/سنة من أي مسجِّل (Namecheap, Cloudflare
   Registrar, GoDaddy...). لا يحتاج أن يكون فعليًا مستضافًا عليه أي
   موقع — فقط تسجيله كافٍ لإضافة سجلات DNS للبريد.

## خطوات التنفيذ الكاملة (بعد توفر الدومين)

كلها في لوحات تحكم خارجية (Resend + Supabase) — لا شيء منها يمر عبر
الكود أو هذا المستودع:

1. أنشئ حساب في [resend.com](https://resend.com) (مجاني).
2. Resend Dashboard → Domains → Add Domain → أدخل دومينك.
3. أضف سجلات DNS التي يعطيك إياها Resend (عادة SPF + DKIM + أحيانًا
   DMARC) عند مسجِّل الدومين — تفعيلها يأخذ من دقائق لعدة ساعات.
4. بعد التوثيق (Verified ✅): Resend Dashboard → API Keys → أنشئ
   مفتاحًا، أو استخدم بيانات SMTP مباشرة (تظهر في نفس الصفحة).
5. Supabase Dashboard → Project Settings → Authentication → SMTP
   Settings → فعّل "Enable Custom SMTP" وأدخل:
   - Host: `smtp.resend.com`
   - Port: `465` (SSL) أو `587`
   - Username: `resend`
   - Password: مفتاح API من Resend
   - Sender email: عنوان على الدومين الموثَّق (مثلاً `noreply@yourdomain.com`)
6. Authentication → Email Templates → Magic Link → عدّل محتوى القالب
   واستبدل `{{ .ConfirmationURL }}` بـ `{{ .Token }}` (يمكن ترك بقية
   النص عربيًا كما تريد، المهم وجود هذا المتغيّر تحديدًا).
7. اختبر تسجيل الدخول فعليًا من التطبيق على بريد حقيقي.

## بعد التفعيل

- لا حاجة لأي push أو تعديل كود لهذا التغيير — إعداد بحت على مستوى
  المشروع في Supabase/Resend.
- Rate limit الافتراضي بعد تفعيل SMTP مخصص: 30 مستخدمًا جديدًا/ساعة
  (قابل للتعديل من Auth → Rate Limits لاحقًا لو احتجت رفعه).
